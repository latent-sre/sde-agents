## What landed

- **The advisory/approval split** in `agents/code-reviewer.md`: the existing PROVISIONAL form
  is the advisory mode and stays legal on a mutable tree; a formal **approval** binds to
  immutable identity — `candidate_sha`, `base_sha`, `tree_oid` — is refused or marked
  provisional on a dirty tree, and **never transfers**: an approval for SHA A says nothing
  about SHA B, however small the delta. A formal approval emits the six-field envelope
  (repository, `base_sha`, `candidate_sha`, `tree_oid`, scope, acceptance criteria); an
  approval missing any of the six is not a formal approval.
- **The `tree_oid` rename** — the one field-name decision that changed at review. The
  originally planned `tree_digest` collides with `evidence_envelope.py`'s SHA-256-typed field
  of the same name inside one verifier flow, so the GRAPH-004 "rename-free" rationale was
  false for that field; the git tree object id name is the fix, `candidate_sha`/`base_sha`
  keep the GRAPH-004 idiom.
- **The envelope on the verifier side** (`agents/verification-engineer.md` Method 1):
  verification of a formal approval requires the envelope, confirms identity before executing,
  and fails closed to inconclusive on mismatch, relevant uncommitted changes, or an
  unreproducible snapshot; evidence destination is declared by the caller — no auto-committed
  bundles into product repositories.
- **The shared material-risk matrix**, canonical in `code-reviewer`, carried verbatim by
  `verification-engineer` with the declared owner, registered in README's owned-conventions
  list. Seeded with exactly the two field-proven controls; the operator's approval condition
  is stated inside the block itself: entries enter only as general controls, never as
  incident notes.
- **Evidence-provenance classes on the reviewer side**: "fresh immutable review plus
  caller-reported test evidence" and "independent verifier executed the approved target" are
  distinct result classes, never one PASS — completing the half GATE-001 shipped on the
  verifier side.
- **Both riders**: `lc_90dd8dc7` → verification-engineer Method 4's whole-branch cold rerun
  (on a multi-task branch where any task edits shared execution configuration, per-task greens
  do not compose — a green produced in a warm world is evidence about the warm world);
  `lc_2c04ead3` → code-reviewer's repro evidence class (a finding's reproduction claim is
  labeled executed or reasoned; a repro the reviewer did not run is never presented as the
  confirmed trigger).
- **Three behavioral contracts**: `reviewer-approval-does-not-transfer`,
  `verifier-envelope-mismatch-fails-closed`, `reviewer-formal-approval-emits-envelope` —
  positives-first graders; the existing dirty-tree contract pair stayed untouched.
