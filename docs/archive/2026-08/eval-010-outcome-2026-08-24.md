# EVAL-010 outcome — per-command Bash evidence

**Status:** Closed 2026-08-24.

## Outcome

The `handoff-digest-rejection` semantic evidence now records every observed Bash command in
transcript order with one outcome: `ok`, `denied`, `error`, or `no-result`. Comparison-grade
`benchmark.json` identifies each command by ordinal, expected-command match, and SHA-256 rather
than retaining its potentially sensitive text. A failed run adds the full command to the existing
protected evidence form, so diagnosis can distinguish a component error from a harness permission
denial or a missing correlated result without buying another model session.

## Re-derivation from the donor

The preserved donor change at `3be1e3e` mixed the evidence repair with an exact-command settings
grant, an evaluator-seeded hashing script, and a rewritten digest command. Those permission and
workspace mechanisms were not ported: current main already grants the case's declared Bash surface
through `--tools` plus `--allowedTools`, and its existing regression
`test_nonempty_allowlist_bounds_the_surface_and_grants_permission` pins that newer design. The
current digest command and workspace contract also remain covered by
`test_digest_rejection_requires_exact_hash_command_and_unchanged_workspace`.

Only the still-live evidence contract was re-derived onto the current transcript parser. The six
donor-derived outcome tests cover successful execution, both retained permission-denial forms, a
generic command error, no correlated result, ordered evidence for every observed command, and
nested error content. A seventh negative proves application output containing approval language
remains a command error rather than being misattributed to the harness. An artifact-level regression
proves the default benchmark omits raw command text while the owner-only failing-run sidecar retains
it beside the outcome. This keeps the donor's diagnostic outcome while avoiding a stale cherry-pick
over the 2026-08-15 grant fix and the later result-classification work.
