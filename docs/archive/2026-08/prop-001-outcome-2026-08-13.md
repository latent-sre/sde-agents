# PROP-001 outcome record — 2026-08-13

**Status: closed.** Imported from GitHub issue #126 (`field-feedback`) per `docs/README.md` rule 7,
implemented on `fix/126-right-size-tier2` and merged as PR #128 (merge `24f8711`), shipping in the
0.7.4 manifest bump — the `sde-agents--v0.7.4` tag. Two follow-ups closed defects this round shipped:
PR #130 (merge `279d383`) and PR #131. The round ran without a spec or plan document; it was a

## The reported failure

A real Codex-host session set one reversible VM CPU model and produced 2,665 lines of transactional
deployment machinery across two commits, 2,404 of them retained. The native control-plane change and
reboot worked on the first try. The agent never led with the operator-visible fact that the VM would
restart and its uptime would reset.

## What landed

- **A "Right-size before designing" section in `agents/homelab-platform.md`, placed before the
  authority tiers.** Position is the fix: "operate like production" and "config as code" were read
  before any proportionality rule, so the agent designed a deployment system before considering
  whether one was warranted. Extra machinery is gated on a **named risk** — custody, data or backup
  semantics, access path, concurrency, multi-host, non-trivial compensation, recurrence — rather
  than on a size heuristic, because "keep it small" is unfalsifiable and "name which of these seven
  applies" is checkable against the packet.
- **`What you will see` leads a Tier 2/3 approval request.** Presence was never the defect: the
  reported session *did* disclose the restart, fourth, inside blast radius, in infrastructure
  vocabulary.
- **Prime directive 1 reworded — the cause the field report did not name.** "State the rollback plan
  in one line before touching anything" reads temporally to a human and positionally to a model.
  Runs opened with a `Rollback` section, one annotating it `(stated before any action, per
  directive 1)`. Rewording it moved the ordering contracts from 0/6 to 5/6; nothing else did.
- **`scripts/packet_lint.py` gained its first ordering rule** (`SHAPE_LEAD_SLOT`) and a
  `tier2-approval-request` shape. Every other shape is an unordered set, right for an end-of-task
  packet; an approval request is a sequence.
- **`scripts/fleet_doctor.py` warnings exit 3.** The Codex standalone-agent drift check already
  existed and already reported WARN — and exited 0, so the doctor agreed with any caller asking
  "is this healthy?" while printing that it was not. The doctor was also absent from `AGENTS.md`,
  which is why the operator found the drift the hard way through `install_codex_agents.py --check`.

reader by design — not a session-time guarantee, and nothing in this round should be read as one.

## What this round cost, and where

Three defects shipped and were caught downstream rather than in review — the pattern worth keeping.

- **PR #128 merged three minutes after opening with no review.** `AGENTS.md` said the automated
  passes "arrive two to five minutes behind `gh pr create`". They do not: they follow an explicit
  `review_requested` event by about ten minutes, and requesting is an **operator** step —
  `copilot-pull-request-reviewer[bot]` is absent from `suggestedActors`, so no CLI path resolves it.
  Phrased as a wait rather than an action, the rule produced a session obediently waiting for a pass
  nobody had asked for. Corrected in PR #130, and the contradicted ledger candidate
  (`lc_eaf272970965435085e743ea6fbaca10`) retired as superseded rather than dropped — its
  `expected_behavior` was never wrong, only its mechanism.
- **The exit-3 change regressed a Codex snapshot host within the hour.** `codex plugin add` writes
  `.codex-marketplace-install.json` into the snapshot it installs from; unignored, it made
  `repository.worktree` warn forever on a host whose only checkout *is* that snapshot. A status
  that is always non-zero teaches an operator to ignore it — the same silence the exit code was
  changed to break. Fixed in PR #130, anchored to the snapshot root in the same PR after review
  showed a slashless pattern also hides a nested occurrence.
- **A fixture running a real `git status` inherits the developer's global git config.** It bit twice
  in one PR: `core.excludesFile` could make the non-vacuity proof pass without the rule (false
  green), and `status.showUntrackedFiles=no` fails three cases on that machine alone (false red,
  reproduced at exit 1). Both pinned in PR #131. A hermetic-git helper in `tests/support.py` would
  prevent the class, and is deliberately **not** built: one consumer today, so it waits
  trigger-bound like any other mechanism.
