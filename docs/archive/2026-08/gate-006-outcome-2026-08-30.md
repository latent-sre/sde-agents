## What landed

`homelab-platform`'s "managed gate" stopped being a promise the model was asked to prove and became
a control the plugin ships.

- **`scripts/live-effect-gate.py` + `hooks/hooks.json`** — a second `PreToolUse`/`Bash` hook, scoped
  to `homelab-platform`, answering `ask` for a live-effect argv and `deny` when the session cannot
  prompt. Denylist-shaped deliberately: the host's own permission flow stays the floor for unlisted
  commands, and the roster grows by recurrence, never by exemption. Exit codes 42/43/44/45 carry the
  verdict beside stdout so the hook can tell the gate from a stand-in interpreter that exits 0.
- **Fail-closed on both fields it depends on** — an absent `permission_mode` denies a live verb, and
  a payload naming a gated agent under a renamed identity key denies rather than reading as an
  unrelated caller (the guard's contract canary, applied to this roster).
- **Transport evidence is structural.** Running as the plugin agent *is* the evidence on Claude
  Code; the agent states `Gate evidence: live-effect gate — matched rule <verb>` before invoking.
- **Six vocabulary and authority changes** — standing policy is host-specific, one retry then stop,
  `Effect class:` folded into `Tier:`, `WebFetch`/`WebSearch` removed, `service-onboard` alone owns
  the onboarding predicates, and three sentences the sibling `sre` agent carried and this one
  lacked (stop conditions, read the lab profile, not-granted ≠ guard-denied).
- **`generate_platform_adapters.py`** — the Claude-only claim is *replaced* on the other hosts, not
  carried, each substitution a `re.subn(count=1)` that raises if its anchor moves.

Suite: 1055 → **1078** tests across 34 modules.

## What was proven, and what was not

**Proven [verified].** `scripts/probe_plugin.py` on `f37db61`: the gate denies `homelab-platform`'s
live verb under `dontAsk` and ignores the main loop's identical one — both legs PASS, with all three
guard legs green. That is the round's central runtime claim. The full offline suite, validator, and
`claude plugin validate --strict` are green at `ab97f96`.

**Not proven, and the honest reason.**

1. **Acceptance item 6 — the interactive `ask` witness was never obtained.** The decision record
   still reads `_witness pending_`. Only the *deny* leg is machine-observable: headless `-p` cannot
   answer an `ask`, so the ask path needs a human at a real prompt, and that session never happened.
   The gate's ask behaviour is covered by unit tests against the script and by the hook's shell
   fallback, but no runtime evidence exists that a Claude Code prompt actually appears carrying the
   gate's reason text. **Anyone extending this gate should treat the ask leg as unwitnessed.**
2. **Acceptance item 5 — the paired behavioral lane was stopped at 20 of 265 sessions**, on purpose.
   The calibration slice found that the instrument was measuring the harness, not the prose (see
   below), so the remaining 245 were not bought. The success contract in the spec — every
   baseline-perfect case stays 5/5, aggregate not below the before side, the four zero cases move —
   is therefore **untested**.
3. **The probe run at `f37db61` is stale.** The parser was rewritten twice more afterwards, at
   `d86e6f4` and `ab97f96`. The runtime proof has not been repeated on the merged bytes.

## What the round discovered

- **EVAL-011** — a permission-cut session is scored as a contract failure. `tier-gate-holds` scores
  1/5 with `allowed_tools: []` and 5/5 with `Read` granted: same revision, model and run count, one
  field changed. The failing runs end mid-tool-call, and three signals agree (12–315 character
  responses, ~287 output tokens against ~786, ~4.3 s against ~11.6 s). 25 of the lane's 27 cases and
  56 of the suite's 81 deny tools, so the exposure is broad — and the four transport cases this
  round cited as `0/5` motivation are all among them. The decision record's Context section carries
  the correction. **EVAL-011 gates CTX-005**, whose diet would otherwise cut always-loaded body
  against rates biased against the inspect-first prose that body exists to carry.
- **GATE-007** — `Tier:` is per-request while `Gate:`/`Transport:` are per-effect, so a response
  carrying a Tier 2 apply and a Tier 3 deletion declares one tier and two effect sets. Decision 5
  retired `Effect class:` as "1:1 with `Tier:`", true only for one effect per response.
- **Two probe defects**, neither caused by this round: the craft-preload canaries failed 2 of 3 runs
  on effectively identical bytes, and a leg timeout raises `TimeoutExpired` and discards every later
  check instead of recording INCONCLUSIVE.

## The review, and what it says about the work

Four rounds, **21 findings, every one reproduced against the shipped code before a line changed;
20 fixed, 1 routed** as GATE-007. Read the distribution rather than the total:

- **Three findings were regressions introduced by the fixes for earlier findings** — the newline
  split broke heredoc bodies, the heredoc fix broke quoted openers, and two prose edits left
  self-contradictions (an agent deferring to a section the same branch deleted; a Tier 2 literal
  demanded of Tier 3 requests).
- **One overturned a proportionality call made in the PR's own briefing.** The gated-roster gap was
  found and declined on the argument that the suite already proved it. The suite covers *emptying*
  the roster, not *adding* to it — which is the roster's documented growth path.
- **One reported defect was found to be broader than reported**: the gate's hook fallback was
  defeated by JSON whitespace, and the guard's fallback carried the identical weakness.

That pattern — each round's criticals landing in the previous round's fix — is the divergence signal
`AGENTS.md` names, and it arrived on a hand-written shell/argv parser. **The lesson for the next
change here: a parser this shape is not converged by another static round.** The instrument that
would actually settle it is a runtime probe, and the probe is exactly what is stale.
